Help improve the project.

The most useful contributions start with a reproducible issue, a focused change, and tests that explain the expected behaviour.

Report a problem

Search existing issues first. Include your environment, exact command, observed output, and the smallest reproduction you can provide.

Open GitHub issues →

Propose a change

Describe the problem a change solves before expanding its scope. Keep pull requests focused and include regression tests when behaviour changes.

Review pull requests →

Find a starting point

Browse issues marked for new contributors and read the repository contribution guide before opening a pull request.

Good first issues →

Before submitting

  • Check whether the issue or proposed change already exists.
  • Keep the change limited to one concern where possible.
  • Add or update tests for changed behaviour.
  • Run the relevant checks and include their results in the pull request.
  • Document compatibility or migration effects when they apply.
